# 项目状态
核对日期：2026-10-20；范围：公共账号中心；依据：docs/acceptance.md、tests/integration-fixes.test.ts、本机隔离库及浏览器验证。

## 项目目标
基于 Casdoor 提供公共账号、独立产品权益及可靠任务恢复；仅修改本仓库，不部署线上。

## 当前状态
本轮管理员设置及接入修复完成。本机服务保留 Casdoor5300、中心5310、两个示例5311／5312、PostgreSQL5342；GitHub仓库继续使用main，交付版本以该分支提交为准。真实拼豆尚未接入。

## 已完成
- 首次本机一次性授权设置用户名／密码，默认admin；只监听回环地址，校验授权、Host和Origin，完成及已有初始化后关闭。经官方初始化导入，支持自定义首个用户名；临时输入在成功后清除，不另建密码系统。
- 管理员“账号与安全”重新认证进入Casdoor原生改密；本机隐藏输入恢复命令 `npm run admin:reset-password`。按稳定subject定位，保留UID、权益及旧审计，恢复追加审计并撤销旧会话。仅管理组织改为至少8位、不要求组合或定期更换；消费者规则保留。
- HOST／PORT与公开URL分离，同步启动健康检查、环境与systemd模板。
- 产品后端独立凭据查询、释放／返还已有任务，不依赖失效／退出／封禁用户令牌，不允许新开消费；严格产品归属，幂等变更并保留流水和恢复审计。
- 示例任务持久化预占ID、原请求号和待恢复状态；确认响应丢失先查事实，后端可继续交付或返还。前端刷新恢复原请求号，待核实时阻止另开任务。
- 产品应用与独立凭据从config/products.json读取，新增产品无需改鉴权分支；后台业务元数据与鉴权配置状态分开显示。真实产品只用OIDC／API，不连接中心数据库。
- 既有运营、权益、兑换及官方Dummy订阅闭环保留；本轮未重新执行支付或前轮全量测试。

## 当前进行中
本轮本地开发及定向验收已完成；真实产品接入与线上部署未执行。

## 关键决策
Casdoor v4.22.0负责唯一身份及安全存储；issuer+subject映射UID，不删除重建管理员。原生欢迎页不覆盖已有管理员，首次自设通过本机授权后的官方导入完成。预占／确认仍要求有效用户身份，恢复入口只允许可信产品后端定位本产品已有记录。机器凭据自动生成，私密环境、数据、日志与测试产物不入Git。

## 已知问题/阻塞
短信、邮件、微信及真实支付商户未配置；消费者邮件／短信找回仍不可用。Linux、systemd、真实反代HTTPS、真实产品、生产并发与跨版本升级未验收。入口构建包仍超过500KB。没有webhook或推送式back-channel logout。
