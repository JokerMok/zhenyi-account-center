# 公网部署实际验收（2026-10-21）

这是本轮在既有tencent-main上的定向验收；[本地历史验收](acceptance.md)中的完整协议、并发扣次等结果没有冒充本轮重新在生产执行。没有运行会大量创建记录或更改配置的本地全量脚本。

## 环境与发布

- Ubuntu26.04 x86_64、4核、7.5GiB内存；部署后约5.2GiB可用、磁盘23GiB可用。服务器时区Asia/Shanghai。
- 官方Casdoor v4.22.0 Linux x86_64包与独立Node.js v22.23.3均已按官方SHA-256核验。PostgreSQL17.11使用官方固定摘要、独立Compose与数据卷；没有复制Mac二进制、测试数据库或两个演示后端。
- 正式HTTPS个人中心 `https://accounts.shizibandu.icu/`，唯一后台 `/admin`，issuer `https://identity.accounts.shizibandu.icu`。DNS解析至既有服务器，TLS正常；Caddy只新增本站配置，校验后reload。
- `/srv/apps/zhenyi-accounts/current/RELEASE.json`记录确切Git提交、上游版本、构建时间与逐文件摘要；最终部署与GitHub提交以该文件和Git记录交叉核对，不把文档自身SHA硬编码进同一提交。

## 本地受影响检查

本轮生产运维、统一认证与统一页面定向13项通过；后续静态／上传修复后生产运维＋统一页面10项通过，最后静态别名修复的5项再验通过。重复执行不计为新增测试数量。TypeScript、业务前端构建和完整原生前端正式URL隔离构建通过，未执行无关全量测试。

已处理实际失败：Mac AppleDouble的`._*.sql`被误识别迁移（事务回滚，未清库）；新增严格迁移名与无Mac元数据打包。初次备份递归测试失败后修复目录递归。原生文件会话写入授权、反代限流来源、缺失上传资源200/HTML及存储关联均纳入源码，后续克隆可重建。原生默认对象的/static资源路径通过资产别名兼容，未重写用户头像或品牌。

私密证据在本机`.local/production-*.log`与服务器`shared/backup-last.json`、`shared/restore-verification.json`，不提交用户ID、密码、会话、数据库或还原内容。服务器项目PROJECT.md记录最终发布状态。

## 外部依赖与验证边界

- 邮件、短信、微信／第三方身份、真实支付商户、外部目录、模型及远程工具凭据尚未配置；页面如实显示未配置。基本用户名密码账号中心不依赖它们。
- 真实支付关闭，无Dummy生产购买入口，没有验证真实商户收款、退款或外部通知。
- 公网没有为验收新开真实产品应用／后端调用密钥，因此跨产品任务、并发扣次与返还沿用本机既有专项证据，未在生产重新跑全量矩阵；接真实拼豆时必须按接入指南验收该产品。
- 本轮没有验证整机重启、故障注入式生产备份失败或真正生产数据切换回退；验证的是服务重启、自动备份实际执行和隔离恢复。不能用隔离恢复声称已实际灾备切换。
- 备份当前为同机root私密文件，未配置异机备份；服务器完全丢失仍需外部副本。HTTPS证书后续续期由现有Caddy负责，未模拟长期到期场景。
