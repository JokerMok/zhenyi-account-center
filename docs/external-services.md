# 外部服务配置与验证清单

全部使用 Casdoor v4.22.0 原生配置页面与后端逻辑。管理入口 http://localhost:5310/admin/providers 、http://localhost:5310/admin/applications 、http://localhost:5310/admin/syncers 。本机未接入真实商户或员工系统。保存不是验证成功；缺项在统一后台“系统设置→配置与诊断”读取实际提供者配置后显示。已保存的敏感配置只由原生权限和脱敏接口处理，中心状态接口不返回密钥。

| 能力 | 最少需要提供／配置 | 原生验证与回调 | 当前边界 |
| --- | --- | --- | --- |
| 邮件与找回 | SMTP主机／端口、TLS方式、发信地址、授权密码；或目标邮件提供者凭据 | 提供者详情测试发送，真实邮箱收信后验证找回；邮件验证码走原生verification API | 未配置；没有伪造发送成功 |
| 短信与短信MFA | 服务商账号密钥、签名、模板、国家／地区和接收测试号码 | 提供者测试、注册／找回／MFA实际收码 | 未配置 |

| 数据库同步 | 独立源数据库、只读账号、表与字段映射、可信主机 | Syncer测试连接／Run；再次Run验证幂等 | 独立本机PostgreSQL源已通过；真实业务源未接 |

| Kerberos | 域、KDC、SPN、keytab、持有票据的客户端 | 原生Kerberos登录入口 | 未配置 |
| WebAuthn／Passkey | HTTPS可信域或localhost、支持的浏览器与系统认证器／安全密钥 | 账号安全→注册→真实用户硬件确认→登录 | 需要用户／硬件确认；未伪造验收 |
| 人脸／钱包／扫码 | 对应设备、钱包或原生提供者配置及用户授权 | 原生登录方式；需要用户确认的动作由用户执行 | 未启动摄像头或签名钱包 |

独立A2A协议、独立LLM模型管理／推理未在固定源码中发现，不属于“等待API Key就能启用”的功能，见固定版本证据清单。

## 注册邮箱与密码找回

消费者注册要求填写邮箱。未接通发信服务时，注册校验邮箱的格式和唯一性，所有权尚未验证。接通后，找回密码用注册邮箱接收验证码。已有无邮箱账号可在登录后的账号安全页绑定邮箱，绑定需要发信服务支持 `reset`。

在管理后台的「身份认证 → 提供商」配置邮件服务并实测收信。将提供商关联到消费者应用，找回密码选择 `forget`，如需同一服务处理绑定邮箱与注册验证可选择 `All`。验证实际收信及重置密码后，可在应用的注册字段中启用邮箱验证码。

新部署默认将邮箱设为必填。对现有部署，从项目根目录执行 `node scripts/require-signup-email.mjs --application=zhenyi-center` 预览，追加 `--apply` 生效。多个消费者应用可重复指定 `--application=应用名`。操作通过 Casdoor 官方接口执行，原注册字段保存到私密运行目录。

## 2026-11-10 模型中转连通性

从正式账号中心所在腾讯云服务器向 `https://api-relay.shizibandu.icu/v1/chat/completions` 实际调用 `gpt-6.1-terra`：普通请求200 application/json且收到文本；流式请求200 text/event-stream，收到3个数据块及[DONE]。Key由本机私密文件经SSH标准输入临时提供，没有写入服务器文件、代码或日志。此结果更新此前“腾讯云直连待测”的状态。

这仅证明模型服务连通。固定v4.22.0的Agent字段为url/token/application，提供者类别没有AI，也没有模型推理客户端；不能把模型Base URL填进Agent监听URL就宣称接入。当前没有新增Agent或将模型Key误写到Agent令牌中。按用户后续确认，模型配置与产品授权由独立业务扩展实现，详见[模型 API 与 AI 产品接入](ai-products.md)；Casdoor原生边界不变。
