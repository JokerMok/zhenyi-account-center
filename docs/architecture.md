# 页面与服务职责

## 三种使用场景

- 产品内用户模块：5311拼豆工坊、5312专注录屏分别有自己的布局、账号菜单与会话。仅显示当前产品会员／次数；登录使用公共OIDC，任务在自己的后端执行。可复用 `examples/product-client.ts`，不复制个人中心或嵌入iframe。
- 公共个人中心：5310根路径，负责个人资料、安全入口、跨产品权益、兑换和记录。没有运营导航；`product`只影响展示与返回上下文，不授予权限。
- 唯一管理后台：5310 `/admin`，固定Casdoor v4.22.0完整React应用是唯一外壳。原生页面和业务页面共用BrowserRouter、AppLayout、侧栏、管理员与面包屑。默认首页是可操作的管理首页；覆盖及依赖详情移至系统设置→配置与诊断。

## 路由与网关

| 路径／端口 | 职责 |
| --- | --- |
| 5310 `/admin/*` | Casdoor原生React路由，`/admin/business/:page`为同一Outlet中的业务内容 |
| 5310 `/admin/api/*` | 流式代理原生API；只转发该浏览器管理员原生会话，不注入管理员服务端凭据 |
| 5310 `/api/admin/*` | 权益管理API；继续核对可信管理员subject、独立会话、CSRF与变更原因 |
| 5310 `/api/*` | 个人中心API及受产品后端密钥保护的权益服务 |
| 5310 `/admin/assets/*`、`/admin/static/*` | 原生构建文件与本地内置资源，缺失返回真实404 |
| 5300 | 公共身份网关；原有OIDC issuer、注册、安全和消费者商业流程保留；旧管理页面转向统一后台 |
| 5305 | 原始Casdoor Go后端，仅回环内部使用，不对外反代 |
| 5311／5312 | 独立示例产品后端、会话、任务及界面 |
| 5342 | PostgreSQL；身份库与权益库使用不同角色 |

公开URL只用于访问、来源校验与回调。监听使用显式HOST／PORT；`CENTER_URL=https://accounts.shizibandu.icu`不要求监听80或root。身份网关使用CASDOOR_PORT（默认5300），原始后端使用CASDOOR_BACKEND_PORT（默认5305）。此次只移动内部端口，不改变可信issuer、client ID、密钥或回调。

管理员授权页在同源 `/admin/login/oauth/authorize`，令牌交换与issuer校验仍使用配置的CASDOOR_URL。代理将原生会话映射为HttpOnly、Path=/admin的 `zy_identity_admin` Cookie；不会读取根路径消费者的 `casdoor_session_id`。生产追加Secure；不设置父域Cookie。原生API与业务API分别执行权限检查，只有前端路由可见不能取得数据权限。

## 数据归属与追溯

Casdoor保存身份、密码、组织、权限与商业原始记录；权益服务保存稳定UID、业务产品、会员投影、额度桶、任务预占／消费／恢复和审计。业务代码不直接操作Casdoor表。原生用户详情用其稳定subject查询权益服务，结合固定可信issuer映射UID，不按用户名、昵称或邮箱合并。

商业商品／商业套餐和业务产品／权益套餐分别命名。订阅由可信服务端查询核对，不以浏览器返回页认定付款；失败不清空有效投影。原有账目事务、幂等、超时释放与后台恢复未重写。管理员历史读取不触发免费额度发放。

## 可重建与回退

`upstream/console/`、共享业务内容、资源清单及编译脚本均纳入Git。构建从已校验的官方归档重置补丁目标，应用React扩展后构建；不依赖被忽略目录的手工改动。保留Apache-2.0及字体／旗帜资源许可。详见 [资源构建](resources.md)、[上游差异](../upstream/extensions/native-navigation.md)。

本轮没有数据库结构迁移。旧管理查询参数由服务器与React兼容转换；保留现有账号、权益、审计。回退先用新脚本停止所有本项目服务，再切回旧提交和旧内部端口配置；身份数据不降级、不清库，详见运维文档。
