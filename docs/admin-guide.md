# 管理员使用与配置

消费者中心：http://localhost:5310 。完整管理入口：http://localhost:5310/admin 。Casdoor 原生工作区：http://localhost:5300 。管理员组织 `built-in`，消费者组织 `consumers`。使用当前已有管理员，不重复初始化；本轮未变更其账号、密码、subject 或 UID。

## 登录与密码

首次 `npm start` 输出仅本机可使用的一次性设置链接；已有初始化数据不会重新开放。以后直接用原账号登录。账号与安全 → 个人资料与密码：重新认证后进入 Casdoor 官方安全页面，完成后返回后台重新登录。忘记密码运行 `npm run admin:reset-password`，两次隐藏输入；命令通过官方接口改密、撤销OAuth令牌及原生会话、清除业务会话和旧初始化明文材料，验证新密码，失败会报告实际阶段。普通密码至少8位；不要求复杂度组合或定期更换。当前本地临时验收密码保持原值，不写入仓库和生产默认配置。

## 完整工作区

`/admin` 显示运行版本、模块实际接口状态、检查时间与外部缺项。选择任一原生模块直接进入该模块完整页面；列表、详情、创建、编辑、停用等仍使用原生实现和官方API。原生左侧增加“臻一业务扩展”，可返回业务产品、功能、套餐、用户权益、兑换码、任务恢复、流水和审计，无需维护第二个管理员。管理员和消费者组织仍严格隔离；中心业务权限额外核对可信管理员稳定subject。

- 身份／组织／应用／协议／提供者／MFA／角色策略／资源／商业原始记录：在原生工作区管理。
- 产品功能、业务会员天数、次数与兑换码：在业务扩展管理。Casdoor支付优惠券和注册邀请码不是权益兑换码。
- Casbin“模型”是权限策略模型。AI与MCP包含上游智能体、服务器、入口、站点和规则；没有据此虚构独立LLM推理功能。

## 产品接入与权益操作

产品“业务启用”与“鉴权登记”分别展示。“检查配置”核对服务端登记、应用client ID和精确回调，并记录时间、环境及缺项。通过仅说明配置一致；实际产品登录／扣次／恢复／隔离的验收时间未登记时明确显示尚未登记，不将演示产品作为真实产品验收。

用户权益抽屉只有一个产品选择。先看当前会员和次数来源，再选开通／续期／撤销／赠送，核对预计结果并填写原因。提交后显示服务端实际结果。管理员只读查看封禁账号或停用产品不会发免费次数。测试账号须主动标记并填写原因；名称前缀只供参考，不再自动决定测试筛选。

额度明细区分免费、管理员、兑换和订阅，展示预占和到期。过期桶不计入可用余额。每日按UTC 00:00（北京时间08:00）重置，每月按UTC月初（北京时间月初08:00）重置。

“消费与任务恢复”按原业务请求号或预占ID查询账目、流水、恢复审计和已知业务交付事实。确认消费不等于交付；没有产品业务事实时显示未知。运营查询只读；真实释放／返还由授权产品后端按接入协议执行，不能手工伪造交付。

## 订阅与购买

先在Casdoor配置商品／商业套餐／定价，再把业务套餐的 `casdoor_plan` 指向 `consumers/商业套餐标识`。中心使用可信服务端查询投影，记录同步处理中、成功、部分异常或失败，显示最近尝试／成功和处理数量。查询失败保留原有权益。真实收费本轮仍关闭；缺商户不能伪造支付成功。

本机官方Dummy测试仅允许回环环境和显式测试账号。`npm run test:purchase -- prepare` 生成本机私密购买fixture；使用其中测试账号在消费者中心完成购买；`npm run test:purchase -- verify` 核对Paid→Active→权益与通知幂等；`npm run test:purchase -- close` 关闭定价和套餐并暂停测试订阅。fixture在 `.local/`，禁止发布。测试结束后没有面向正常消费者的测试购买入口。
