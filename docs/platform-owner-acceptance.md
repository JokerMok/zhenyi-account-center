## 实现与边界

- 使用现有 `built-in/admin` 的可信 issuer + 固定 subject，不新增消费者副本，不按用户名或邮箱合并。统一 UID、既有审计和管理员身份保留。
- 各消费者应用登录页新增“平台管理员登录”，保留当前应用的授权参数，使用各自 OIDC 客户端及独立会话。服务端仍检查签名、issuer、audience、Casdoor 实时账号状态及固定超管权限。
- 当前及后续登记的启用产品：永久会员、所有启用功能、次数不限。未登记产品需先正常接入中心；产品本地角色和独立模型授权不自动改变。账号封禁、产品停用、功能停用依然生效。
- 次数豁免不创建巨额额度桶；007 仅为任务增加 `quota_exempt`。任务仍有预占、确认、取消、返还和超时记录，金额为零，保留请求次数，重复操作不增余额。
- 本次通过 Casdoor 官方能力执行一次性密码恢复，随后恢复管理员组织原密码规则。旧原生会话与本中心该 UID 的会话已撤销。未修改消费者规则；启动和恢复脚本不包含本次临时密码，不覆盖后续自行改密。
- 常规改密：后台右上角账号安全入口；交互恢复仍为本机 `npm run production:admin`，或服务器 `sudo /srv/apps/zhenyi-accounts/deploy/manage.sh admin:reset-password`。常规新密码至少8位。
